# Issue tracker: GitHub

Issues and PRDs for this repo live as GitHub Issues in `justbill2020/Lambchop`. Use the `gh` CLI for issue operations from inside this clone.

## Conventions

- **Create an issue**: `gh issue create --title "..." --body-file <file>`.
- **Read an issue**: `gh issue view <number> --comments --json number,title,body,labels,comments,state,url`.
- **List issues**: `gh issue list --state open --json number,title,labels,state,url`.
- **Comment on an issue**: `gh issue comment <number> --body-file <file>`.
- **Apply labels**: `gh issue edit <number> --add-label "needs-triage"`.
- **Close**: `gh issue close <number> --comment "..."` only when the workflow or Bill explicitly permits closing.

Infer the repository from `git remote -v`; `gh` does this automatically when run inside this clone.

## AI triage disclosure

Every issue body or issue comment created through triage must start with:

> *This was generated by AI during triage.*

## When a skill says "publish to the issue tracker"

Create a GitHub issue unless the workflow says the current chat is intake-only and should only queue local work. For Lambchop, GitHub Issues is the durable external discussion tracker, while `docs/lambchop/state.json` remains the executable automation queue.

## When a skill says "fetch the relevant ticket"

Run `gh issue view <number> --comments --json number,title,body,labels,comments,state,url`.

## Safety boundary

Use GitHub Issues for issue tracking by default. Do not open pull requests, deploy, mutate production configuration, or push branches unless `WORKFLOW.md` and `docs/lambchop/state.json` allow that action.
